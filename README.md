## 🎯 Overview

SafeGuard enables safety managers to **track risks, conduct audits, enforce remediation workflows, and generate compliance reports** across hierarchical facility structures. Built for enterprise environments with strict data integrity, role-based access, and complete audit trails.

| Capability | Description |
|---|---|
| **Hierarchical Locations** | 3-level closure-table tree: Sites → Buildings → Areas/Floors |
| **Risk Register** | Full CRUD with severity classification, owner assignment, evidence upload |
| **Workflow Engine** | 6-stage state machine: `OPEN → ASSIGNED → IN_PROGRESS → RESOLVED → APPROVED → CLOSED` |
| **Advanced Filtering** | Combination filters: search + status + severity + date range (AND-logic) |
| **Professional Reporting** | PDF (jsPDF + autoTable) and CSV exports — filtered data only |
| **Activity Logging** | Zero-latency global interceptor logs all mutations to `activity_logs` table |
| **Idempotent Seeding** | Auto-populates DB with realistic Karnataka facility data on first run |

## 🏗️ Architecture Decisions

### 1. TypeORM `@Tree("closure-table")` for Hierarchical Locations

**Problem**: Industrial facilities have deep hierarchies (Site → Building → Floor → Zone). A naive `parentId` adjacency list requires **N+1 queries** to fetch the tree — one query per level.

**Solution**: TypeORM's closure-table strategy creates an auxiliary `location_closure` table that stores **every ancestor-descendant pair**:

```sql
-- Auto-generated by TypeORM
CREATE TABLE location_closure (
  id_ancestor  UUID NOT NULL,
  id_descendant UUID NOT NULL,
  PRIMARY KEY (id_ancestor, id_descendant)
);
```

**Result**: `TreeRepository.findTrees()` executes a **single JOIN query** to reconstruct the entire nested hierarchy:

```typescript
// LocationService — O(1) round-trips regardless of tree depth
async findTrees(): Promise<Location[]> {
  return this.locationTreeRepo.findTrees();
}
```

The frontend's `LocationTreeSelect` cascade dropdown receives the complete tree in one API call, populating all three dropdown levels instantly.

**Trade-off**: Writes are slightly more expensive (inserting a node also inserts closure rows for all ancestors), but reads are O(1) — the correct trade-off for a read-heavy location picker used on every form.

### 2. React Hook Form + Zod (Schema-First Validation)

**Architecture**: Validation schemas are defined once in Zod (`src/schemas/risk.schema.ts`) and shared across:

```
                  ┌─────────────────┐
                  │   Zod Schema    │ ← Single source of truth
                  └────────┬────────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ RHF Form │ │ Frontend │ │ Backend  │
        │Resolver  │ │  Types   │ │class-val │
        └──────────┘ └──────────┘ └──────────┘
```

- **React Hook Form** uses `@hookform/resolvers/zod` to validate on `onTouched` mode — fields validate after first interaction, not on every keystroke (performance).
- **Backend DTOs** (`CreateRiskDto`) mirror every Zod constraint with identical `min/max` lengths and error messages.
- **TypeScript types** are inferred from Zod via `z.infer<>` — zero manual type duplication.

### 3. Workflow State Machine (Strict Enforcement)

The risk lifecycle is enforced at **three layers**:

| Layer | Mechanism | Prevents |
|---|---|---|
| **Frontend** | `WORKFLOW_TRANSITIONS` map → single "Next Action" button | User cannot see/click invalid transitions |
| **Backend Service** | `VALID_TRANSITIONS[currentStatus].includes(targetStatus)` | API callers cannot bypass the UI |
| **Backend Pipe** | `WorkflowTransitionPipe` — injectable validator | Future endpoints inherit protection |

```
OPEN ──→ ASSIGNED ──→ IN_PROGRESS ──→ RESOLVED ──→ APPROVED ──→ CLOSED
                                                                  (terminal)
```

## 🔮 Extensibility Approach

### Adding New Audit Types (JSONB / Dynamic Fields)

The `Audit` entity includes a `notes: text` field, but the architecture is ready for schema-less extensions:

```typescript
// Future: Add a JSONB column for audit-type-specific data
@Column({ type: 'json', nullable: true })
customFields: Record<string, unknown>;
```

Each audit type (Fire Safety, Chemical Compliance, Electrical) can store its unique checklist data in `customFields` without schema migrations. The frontend renders a dynamic form using a `customFields` JSON schema definition.

### Configurable Workflows (Strategy Pattern)

The `VALID_TRANSITIONS` map is a **data-driven state machine** — not hardcoded `if/else` chains:

```typescript
const VALID_TRANSITIONS: Record<RiskStatus, RiskStatus[]> = {
  [RiskStatus.OPEN]: [RiskStatus.ASSIGNED],
  // ...
};
```

**To add a new workflow** (e.g., "Express Close" for LOW-severity risks):
1. Add the new transition to the map: `[RiskStatus.OPEN]: [RiskStatus.ASSIGNED, RiskStatus.CLOSED]`
2. The pipe, service, and frontend all consume the same map — zero code changes needed elsewhere

**To support per-organization workflows**: Move the map to a `workflow_configs` table. The pipe loads the config at runtime based on `orgId`. This is the **Strategy Pattern** — the transition logic is decoupled from the enforcement mechanism.

### Plugin Reporting

The export utilities (`src/utils/export.ts`) follow the **Template Method pattern**:

```typescript
// Adding a new report format (e.g., Excel):
export function exportRisksToExcel(risks: Risk[]): void {
  // 1. Map risks to rows (same as CSV/PDF)
  // 2. Use a library like SheetJS to generate .xlsx
  // 3. Trigger download via Blob
}
```

The `RiskFilterBar` renders export buttons from a configuration array — adding a new format requires one function and one button entry.

## 🚀 Local Setup

### Prerequisites

- **Node.js** ≥ 18.x
- **MySQL** 8.x (running locally or via Docker)
- **npm** ≥ 9.x

### 1. Clone & Install

```bash
git clone https://github.com/your-username/safeguard.git
cd safeguard

# Frontend dependencies
npm install

# Backend dependencies
cd backend
npm install
cd ..
```

### 2. Database Setup

```bash
# Create the MySQL database
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS safeguard;"

# Configure backend environment
cp backend/.env.example backend/.env
# Edit backend/.env with your MySQL credentials:
#   DB_HOST=localhost
#   DB_PORT=3306
#   DB_USERNAME=root
#   DB_PASSWORD=your_password
#   DB_DATABASE=safeguard
```

### 3. Start Development Servers

```bash
# Terminal 1: Backend (auto-seeds DB on first run)
cd backend
npm run start:dev
# → 🛡️ SafeGuard API at http://localhost:3001/api/v1

# Terminal 2: Frontend
npm run dev
# → ⚡ React app at http://localhost:5173
```

> **Note**: The frontend works with or without the backend running. If the API is unavailable, Zustand falls back to mock data automatically.

### 4. Verify

```bash
# Check API health
curl http://localhost:3001/api/v1/risks

# Check location tree
curl http://localhost:3001/api/v1/locations/tree
```

## 📡 API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/v1/locations/tree` | Full hierarchical location tree |
| `GET` | `/api/v1/locations/:id/descendants` | Subtree from a specific node |
| `GET` | `/api/v1/locations/:id/ancestors` | Ancestor path to root |
| `GET` | `/api/v1/risks` | List all risks (with Location + Audit) |
| `GET` | `/api/v1/risks/:id` | Get single risk detail |
| `POST` | `/api/v1/risks` | Create new risk (validated) |
| `PATCH` | `/api/v1/risks/:id/status` | Advance workflow state |
| `DELETE` | `/api/v1/risks/:id` | Remove a risk |

## 🏆 Bonus Features

### 🔐 RBAC-Ready Architecture
The `ActivityLog` entity tracks `userId` on every mutation. The `apiClient` interceptor attaches `Bearer` tokens. Auth guard integration requires only a `@UseGuards(AuthGuard)` decorator — the infrastructure is in place.

### 📊 Activity Logging (Zero-Latency)
The `ActivityLoggerInterceptor` uses RxJS `tap()` + fire-and-forget promises to log all POST/PATCH/DELETE operations **without adding any latency** to the HTTP response. Failed log writes are caught silently — they never impact the user experience.

### 📄 Professional PDF Export
- Landscape A4 with branded header ("SafeGuard — Risk Register Report")
- Auto-generated timestamp and total count
- Alternating row colors (white/slate-50)
- "SafeGuard — Confidential" footer with page numbers
- Only exports **filtered data** — what you see is what you get

### 📎 Evidence Upload
- Drag-and-drop zone with file type validation (PNG, JPG, WebP)
- Simulated upload progress (30% → 70% → 100%)
- Thumbnail previews with file removal
- 10MB max file size, 5 files max
